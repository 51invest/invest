Valuation Sensitivity and Scenarios

Test how much a valuation conclusion depends on its key assumptions using sensitivity tables and probability-weighted scenarios; all example numbers are hypothetical.

Problem and output

The input is a base-case DCF, credible ranges for its key parameters and a set of defined scenarios. The output is not a new target price. It is the response of value to each parameter, a scenario range, a probability-weighted value where probabilities are stated, and a list of assumptions worth checking first. The question is "how robust is the conclusion, and what would overturn it?"

Inputs and data requirements

Base free cash flow, a five-year forecast, perpetual growth, the discount rate, bounds for each parameter with a rationale, and scenario probabilities with trigger conditions. Bounds should come from historical ranges, peer ranges or market-implied values, with the source stated. MD&A and risk factors in filings can set scenario triggers. Align the price, statements and forecast to the same date; keep currency and nominal or real treatment consistent; label any probability that is an assumption rather than an estimate.

The SEC investor guide explains that management’s discussion and analysis presents management’s view of results, of known trends or uncertainties that could materially affect results, and of critical accounting estimates and assumptions; when those estimates change the reported figures change, so scenario triggers need a stated source [3].

Assumptions

Teaching assumptions: every amount in this article is in CNY millions; the currency is a label this article invents, pointing at no real company and at no currency-specific data from any source. FCF1 = 100 (that is, 100 million yuan), received at year-end, then 8% annual growth from year 2 through year 5, then 2.5% in perpetuity; r = 9%. EV = Σ FCF_t/(1+r)^t + TV/(1+r)^5, with TV = FCF5 × (1+g∞)/(r - g∞). Base EV is about 1,844.7, and the present value of terminal value is 75.6% of it. Sensitivity changes only r and g∞; scenarios separately change cash flow, growth and discount rate.

The discounting relation here follows OpenStax: each period’s cash flow and the terminal value are discounted at the required return, so terminal value, growth and the discount rate jointly determine value, and the same section lists the limits of the DCF model [2].

Steps

  1. Recompute the base case: FCF5 = 136.0, terminal value PV = 1,394.4, EV = 1,844.7.
  2. Build a 3×3 table for r = 8%, 9%, 10% and g∞ = 2.0%, 2.5%, 3.0%; EV ranges from 1,515.4 to 2,370.4.
  3. Measure one-at-a-time effects: +1 percentage point in r cuts EV by 13.7%; +0.5 percentage points in g∞ adds 6.7%.
  4. Define scenarios: bear (FCF1 = 80, g = 0%, r = 10%, g∞ = 2%), base, and bull (FCF1 = 108, g = 11%, r = 8.5%, g∞ = 3%).
  5. Value them: 936.6, 1,844.7 and 2,563.1.
  6. Weight 30%, 50% and 20%: the expected value is 1,716.0, 7.0% below the base case.
  7. Write the trigger for each scenario (demand, price, cost, rates) and note the tails the scenarios omit.

Forecast first, then scenario, is OpenStax’s order: cash-flow forecasts rest on many assumptions, changing one variable propagates through the formula, recession and expansion scenarios can be compared this way, and growth by itself does not guarantee higher profit or cash [1].

Interpreting the result

The table shows that terminal value dominates: small changes in r and g∞ move the conclusion. The scenario range is 936.6 to 2,563.1, the top about 2.7 times the bottom, and the weighted value sits below the base case, so the base case is not the expected value once a downside is admitted. The weights are judgement, not data. Report the range, the weights and the single-variable elasticities together rather than one number. Sensitivity is a local, one-at-a-time comparison that holds other inputs fixed; if r and g∞ move together, the actual range is wider.

Failure conditions

  • parameter ranges have no rationale, or a sensitivity table is read as a probability distribution
  • r is close to or below g∞, so terminal value explodes
  • scenarios overlap or probabilities do not sum to 100%
  • the same cash flows are paired with different discount rates without a reason
  • tax, FX, dilution or minority interests are ignored
  • the weighted result is presented as a forecast or target price

Verification

Plug each parameter set back into the model; cross-check with an exit multiple or a dividend discount model; test alternative forecast horizons and FCF definitions; confirm the scenario ranking survives an alternative model; record intermediate values so the table can be rebuilt.

Reproduction

Formulas: EV = Σ_{t=1}^{5} FCF_1(1+g)^{t-1}/(1+r)^t + TV/(1+r)^5, TV = FCF_5(1+g∞)/(r-g∞), and E(V) = Σ p_i V_i. Build the 3×3 grid with a spreadsheet data table or a loop, keeping one decimal place.

Working paper: four columns for a checkable judgement

The subject of this article is "INV-012". Do not begin by memorising a conclusion; begin with a four-column worksheet. Column one states the definition, numerator, denominator and unit of "sensitivity analysis". Column two states the transmission channel of "scenario analysis". Column three states the institutional boundary of "terminal value". Column four states the signal that would refute the conclusion. Only when all four are filled may the conclusion travel to the next step; an empty column turns it into an assumption.

Column one is where shortcuts appear. Writing "higher is better" is not a definition. At minimum, answer whether the metric is a stock or a flow, whether the denominator is output, population, assets or transaction volume, whether the price is nominal or real, and whether the observation is an endpoint or a period average. Change any one and the ranking or conclusion can move. If a source gives a number without a denominator, return to its footnote rather than borrowing the denominator from a neighbouring article.

Column two turns "scenario analysis" into an observable chain: which variable moves first, through which intermediary, and which outcome changes last. Every link needs a time and a unit; do not mix "long run" with "quarterly". The longer the chain, the more important it is to mark which link is the author's inference and which link has source support. Inference may teach, but it may not masquerade as fact.

Column three handles institutions. terminal value is not background colour; it is the sample definition. Which entities are covered, which are exempt, when does the rule take effect, and does a cross-border comparison bind the same sample to one rule? Different institutions attach different incentives to the same number. Writing an institutional difference as a behavioural difference is the most common error in cross-market comparison. If the rules cannot be aligned, downgrade the comparison to two separate scenarios and do not rank them.

Column four writes the refutation. End with a falsifiable sentence: "If A is observed and C follows within B, the claim holds; otherwise it fails." A must be observable, B must be a waitable period, and C must be a checkable result. If the three cannot be written, the claim is not testable yet. Keep the worksheet, source links and review date on one page; in the next review, read the four columns before reading the outcome.

Record template

Compress the four columns into one page: measurement and unit on the left, mechanism and institution in the middle, refutation and review date on the right. When data update, change only the numbers and not the conclusion sentence; if the sentence itself must change, the measurement or the institution has changed, so return to the source and redo the check. Keep one column for the opposing view. In the next review, ask whether evidence overturned that view before asking whether the position made money.

A useful record has five fields: the source URL, the access date, the denominator, the rule's effective date and one falsifier. Five fields make the record portable: another reader can reopen the source, recompute the ratio and see which condition would have changed the judgement. A record without them is a diary, not evidence.

Boundary case: A four-cell sensitivity table: discount rates of 8/9/10% and growth of 2/3%

With base free cash flow of 200, perpetual growth g and discount rate r, value = FCF × (1 + g) ÷ (r - g). At r = 8% and g = 3%, value is 4,120; at 9% and 3%, 3,433; at 10% and 3%, 2,943; at 9% and 2%, 2,914. A one-point rise in the discount rate cuts value from 4,120 to 3,433, or 16.7%; a one-point fall in growth cuts it from 3,433 to 2,914, or 15.1%. When both move against the holder, value is 2,943, a 28.6% decline.

The conclusion reverses when the cash-flow forecast moves with the macro scenario: if a higher discount rate comes with stronger growth, free cash flow is also revised up, so moving r without the numerator is wrong. The boundary is that a sensitivity table is conditional recomputation, not a probability-weighted conclusion. If probabilities are attached to cells, they need a basis, not guesswork.

All numbers are teaching assumptions, not investment advice.

A sensitivity table must also state how cash flow and the discount rate move together. If growth changes capital spending and working capital, free cash flow cannot stay fixed; if risk premium rises with leverage, the discount rate is not independent. Each cell needs a consistent set of assumptions, or the table is only a number collage.

Reading and review

Valuation sensitivity is not producing more numbers; it is finding which assumption flips the conclusion. Move revenue growth, margin, discount rate and terminal multiple one notch each and observe the value; then combine variables into optimistic, base and stress worlds. The higher the terminal value share, the more the model depends on long-run assumptions; a small discount-rate change amplifies the terminal effect. Probability weighting does not dress uncertainty as precision; it writes the ranges and correlations of key drivers explicitly. Public references for the institutional definitions are cited [4]; all worked numbers are teaching assumptions.
